 # USER_DOC – Inception Stack (WordPress, NGINX, MariaDB)

This document explains, in simple terms, how to use the stack as an end user or administrator.

## What Services Are Provided
- NGINX (HTTPS): Terminates TLS with a self‑signed certificate and serves WordPress over port 443.
- WordPress (PHP‑FPM): The website and admin panel, running PHP‑FPM internally on port 9000.
- MariaDB: The database used by WordPress.
- Persistence: Host bind‑mounts keep your data under `/home/ner-roui/data/...`.
- Secrets: Passwords are stored as Docker secrets and mounted at runtime.

Logical flow:
```
Client ⇄ HTTPS :443 ⇄ NGINX ⇄ FastCGI ⇄ WordPress (php-fpm) ⇄ MariaDB
```

## Start and Stop the Project
Recommended: use the provided Makefile from the project root.

- Start (generates secrets, prepares volumes, updates /etc/hosts, builds and runs):
```bash
make run
```
- Stop containers:
```bash
make stop
```
- Rebuild and restart from scratch (DESTROYS local volumes and secrets):
```bash
make fclean
make run
```

Notes:
- The domain `ner-roui.42.fr` is mapped to `127.0.0.1` automatically by `make run`.
- A self‑signed certificate is used; your browser will show a warning that you can safely bypass for local testing.

## Access the Website and Admin Panel
- Website: https://ner-roui.42.fr
- Admin Panel: https://ner-roui.42.fr/wp-admin

Credentials (where to find):
- Admin username: defined in `srcs/.env` as `ADMIN_USER`.
- Admin password: stored in `./secrets/admin_password.txt` (generated by `make`).
- Additional user: `USER_TWO`/`USER_TWO_EMAIL` in `srcs/.env` with password in `./secrets/user_password.txt`.

On first startup, the WordPress install is automated. If you reach the site before configuration completes, wait a few seconds and refresh.

## Locate and Manage Credentials
- Secrets directory on host: `./secrets`
  - `db_password.txt` → used for the MariaDB user and injected during WP setup.
  - `admin_password.txt` → initial WordPress admin password.
  - `user_password.txt` → initial secondary user password.

View a secret (example):
```bash
cat secrets/admin_password.txt
```

Important:
- WordPress credentials are created once during the initial setup. Changing files in `./secrets` later will not retroactively change WordPress users.
- To change the WordPress admin password:
  - Use the dashboard: Users → Profile → Set New Password; or
  - Use WP‑CLI inside the container, e.g.:
    ```bash
    docker-compose -f srcs/docker-compose.yml exec wordpress wp user update "$ADMIN_USER" \
      --user_pass="NEW_STRONG_PASSWORD" --allow-root
    ```
- To rotate the DB user password, update it in MariaDB and also update `wp-config.php` accordingly (or fully reprovision via `make fclean && make run`, which wipes data):
  ```bash
  # Change DB user password (example)
  docker-compose -f srcs/docker-compose.yml exec mariadb \
    mysql -e "ALTER USER '${DB_USER}'@'%' IDENTIFIED BY 'NEW_DB_PASS'; FLUSH PRIVILEGES;"

  # Update WordPress config (inside wordpress container)
  docker-compose -f srcs/docker-compose.yml exec wordpress \
    wp config set DB_PASSWORD "NEW_DB_PASS" --allow-root
  ```

## Check That Services Are Running Correctly
- Check container statuses:
```bash
docker-compose -f srcs/docker-compose.yml ps
```
- Follow logs for a specific service:
```bash
docker-compose -f srcs/docker-compose.yml logs -f nginx
# or
docker-compose -f srcs/docker-compose.yml logs -f wordpress
docker-compose -f srcs/docker-compose.yml logs -f mariadb
```
- Test HTTPS locally:
```bash
curl -v https://ner-roui.42.fr
```
- Quick DB check (list databases):
```bash
docker-compose -f srcs/docker-compose.yml exec mariadb mysql -e "SHOW DATABASES;"
```

## Troubleshooting (Quick)
- Browser warns about certificate: expected for self‑signed certs; proceed for local use.
- `https://ner-roui.42.fr` doesn’t resolve: ensure `/etc/hosts` contains `127.0.0.1 ner-roui.42.fr` (added by `make run`).
- WordPress not installed yet: wait a few seconds; the setup script runs after DB is ready. Check logs with `docker-compose ... logs -f wordpress`.
- Port 443 already in use: stop the conflicting service or change the exposed port mapping in `srcs/docker-compose.yml` and adjust access URL.
- Full reset: `make fclean && make run` (this erases local data and secrets).
